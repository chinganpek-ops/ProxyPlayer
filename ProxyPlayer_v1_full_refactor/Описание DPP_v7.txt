Архитектурный план v7: оптимизация для длинных файлов (6+ часов)
Ключевые изменения

Для файлов длительностью 6+ часов текущая архитектура упирается в три узких места:

    Полное построение индекса при старте — даже инкрементальное построение 1200 чанков не решает проблему, т.к. build_audio_tracks обрабатывает все ~3 млн C9-записей

    Линейный поиск по индексу при seek — HybridSeekWorker ищет IDR перебором

    Монолитный ChunkReader — один поток на всё

Предлагаемая архитектура v7
text

┌─────────────────────────────────────────────────────┐
│                  PlayerController                    │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────┐  │
│  │ LazyIndex│  │SeekEngine│  │  StreamScheduler  │  │

Компоненты для реализации

1. LazyIndex — оконный индекс

    При старте строим только окно ±5 минут вокруг текущей позиции

    Остальной индекс остаётся в mmap, читается по требованию

    IndexWindow класс: хранит video_records[start:end], audio_tracks для того же диапазона

    При перемещении за границы окна — асинхронно расширяет/перестраивает окно

    Математика: окно размером 5 минут = 7500 кадров = 625 чанков = ~150 000 C9-записей (вместо 3 млн)

2. SeekEngine — двоичный поиск по mmap

    Вместо линейного перебора idr_frames используем np.searchsorted на всём video_records

    IDR-карта строится лениво: проверка первых N кандидатов, экстраполяция шага

    seek_absolute(frame_idx):

        Бинарный поиск ближайшего IDR в video_records

        Если IDR вне текущего окна — быстрое перестроение окна

        HybridSeekWorker только для декодирования

3. ChunkPipeline — трёхэтапный конвейер

    Этап 1 (Reader): читает сырые данные чанка, кладёт в очередь raw_queue

    Этап 2 (Demuxer): извлекает видео/аудио пакеты, кладёт в video_packets, audio_packets

    Этап 3 (Decoders): отдельные потоки для видео и аудио, забирают из очередей

    Очереди ограничены по размеру (3–5 элементов), при переполнении Reader ждёт

text

Reader ──→ raw_queue (max 3) ──→ Demuxer ──→ video_packets (max 5) ──→ VideoDecoder
                                         └─→ audio_packets (max 5) ──→ AudioDecoder

4. StreamScheduler — приоритетная загрузка

    При нормальном воспроизведении: загружает чанки вперёд на 10 секунд

    При seek: немедленно загружает целевой чанк, затем окрестности

    При JKL-перемотке: загружает каждый N-й чанк (в зависимости от скорости)

    При паузе: заполняет буфер вперёд на 30 секунд

5. Асинхронный SeekEngine (отмена предыдущего)

    SeekEngine работает в отдельном потоке

    При новом seek старый отменяется через threading.Event

    Результат возвращается через callback/сигнал

class LazyIndex:

class IndexWindow:
    video_records: np.ndarray       # DTYPE_193, только в окне
    audio_tracks: np.ndarray        # DTYPE_AUDIO, только в окне
    chunk_offsets: np.ndarray       # int64, только для окна

    window_end_frame: int

    def contains_frame(self, frame_idx: int) -> bool
    
    # Возвращает границы окна в чанках
    def chunk_range(self) -> Tuple[int, int]

    audio_tracks строятся только для нужного диапазона через build_audio_tracks с предварительной фильтрацией C9-записей по PTS

    Размер окна по умолчанию: 5 минут = 300 секунд = 7500 кадров = 625 чанков

Модуль 3: chunk_pipeline.py

Назначение: Трёхэтапный конвейер обработки чанков

API:
python

class ChunkPipeline:
    def __init__(self, mp4_path: Path, video_decoder: Decoder, 
                 audio_decoders: List[AudioDecoder],
                 video_buffer: FrameRingBuffer,
                 audio_buffers: MultiTrackAudioBuffer)
    
    # Запуск/остановка конвейера
    def start(start_chunk: int)
    def stop()
    def pause()
    def resume()
    
    # Обновление данных индекса
    def update_index(window: IndexWindow)
    
    # Приоритетная загрузка
    def prioritize_chunk(chunk_idx: int)
    
    # Состояние конвейера
    @property
    def raw_queue_size() -> int
    @property
    def video_packets_pending() -> int
    @property
    def audio_packets_pending() -> int

class Stage:
    """Базовый класс для этапа конвейера"""
    input_queue: queue.Queue
    output_queues: List[queue.Queue]
    thread: threading.Thread
    stop_event: threading.Event
    
    def run()  # переопределяется в наследниках

class ReaderStage(Stage):
    """Этап 1: чтение сырых данных"""
    def run():
        while not stop_event:
            chunk = scheduler.get_next_chunk()
            raw_data = reader.read_sequential(chunk.offset, chunk.size)
            output_queue.put((chunk, raw_data))

class DemuxerStage(Stage):
    """Этап 2: разделение на видео/аудио пакеты"""
    def run():
        while not stop_event:
            chunk, raw_data = input_queue.get()
            video_packets, audio_packets = demux(chunk, raw_data)
            video_queue.put(video_packets)
            audio_queue.put(audio_packets)

class VideoDecoderStage(Stage):
    """Этап 3a: декодирование видео"""
    def run():
        while not stop_event:
            packets = input_queue.get()
            for pkt in packets:
                frames = decoder.decode_sample(pkt)
                for frame in frames:
                    video_buffer.try_push(frame, pts)

class AudioDecoderStage(Stage):
    """Этап 3b: декодирование аудио"""
    def run():
        while not stop_event:
            packets = input_queue.get()
            for pkt in packets:
                pcm = audio_decoder.decode(pkt.data)
                audio_buffers.try_write(pkt.track, pcm, pkt.pts)

Очереди между этапами:
python

raw_queue = Queue(maxsize=3)        # Reader → Demuxer
video_queue = Queue(maxsize=5)      # Demuxer → VideoDecoder
audio_queue = Queue(maxsize=5)      # Demuxer → AudioDecoder

Модуль 4: stream_scheduler.py

Назначение: Приоритетное планирование загрузки чанков

API:
python

class StreamScheduler:
    def __init__(self, pipeline: ChunkPipeline, index_window: IndexWindow)
    
    # Основной режим: загрузка вперёд
    def set_normal_mode(current_chunk: int)
    
    # Режим seek: приоритет целевому чанку
    def set_seek_mode(target_chunk: int)
    
    # Режим JKL: загрузка каждого N-го чанка
    def set_fast_forward_mode(direction: int, speed: float)
    
    # Режим паузы: заполнение буфера
    def set_pause_mode(current_chunk: int)
    
    # Получить следующий чанк для загрузки
    def get_next_chunk() -> Optional[int]
    
    # Статистика
    @property
    def pending_chunks() -> List[int]
    @property
    def loaded_chunks() -> Set[int]

Внутренняя логика:

    Нормальный режим: последовательная загрузка вперёд на lookahead = 10 сек / длительность чанка чанков

    Режим seek: целевой чанк → соседние (±2) → дальнейшие

    Режим JKL: stride = max(1, int(speed)), загружается каждый stride-й чанк

    Режим паузы: заполнение до buffer_size - free_slots_required
