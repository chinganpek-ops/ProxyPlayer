Dalet Proxy Player v6

Высокопроизводительный сетевой видеоплеер для воспроизведения растущих (live) и архивных MP4-файлов формата Dalet по протоколу SMB/CIFS. Версия 6 включает трёхбуферную очередь, мгновенный старт, JKL-перемотку, ручной ввод таймкода, неблокирующую загрузку и инкрементальное построение индекса.
1. Архитектура

Плеер разделён на независимые подсистемы, взаимодействующие через потокобезопасные кольцевые буферы.
1.1 Структурная схема
text

main.py
├── ManagerWindow (QLocalServer, QTcpServer)
│   └── PlayerWidget (управляемый плеер)
│       └── PlayerController
│           ├── Decoder (H.264 → RGB24)
│           ├── AudioDecoder (AAC → float64)
│           ├── FrameRingBuffer ×3 (трёхбуферная очередь)
│           ├── MultiTrackAudioBuffer (дорожки 2..17)
│           ├── ChunkReader (фоновая загрузка чанков)
│           ├── HybridSeekWorker (синхронный seek)
│           └── AudioOutput (QAudioOutput, 48 кГц float32)
├── idx_cache (зеркалирование .idx, mmap)
├── moov_builder (построение структур из .idx)
├── win_sequential_reader (чтение через Windows API)
└── video_widget (QOpenGLWidget)

1.2 Потоковая модель
Поток	Назначение

1.3 Синхронизация

    Ведущий: аудио (audio_clock в сэмплах 48 кГц)

    Ведомый: видео (подстраивается под audio_clock)

    Допустимое рассогласование: ±400 мс (MAX_VIDEO_LAG = 19200 сэмплов)

    Коррекция дрейфа: адаптивная оценка реальной частоты аудиовыхода (measure_interval = 2 с, α = 0.3)

2. Трёхбуферная очередь

Для мгновенной перемотки используется три независимых кольцевых буфера:
text

buffer_main      – основной (воспроизведение)
buffer_background – фоновый (наполнение при seek)
buffer_standby   – резервный (захват первого кадра)

2.1 Циклический сдвиг при seek

    HybridSeekWorker заполняет buffer_background

    buffer_main ↔ buffer_background

    buffer_background.clear()

    buffer_standby используется для мгновенного захвата первого кадра при старте

2.2 FrameRingBuffer

Кольцевой буфер видео-кадров (PTS: int, frame: np.ndarray RGB24).

Параметры:

    max_frames: 300–800 (настраивается)

    Потокобезопасность: threading.Lock + threading.Condition

Ключевые методы:

    try_push(frame, pts) – неблокирующая вставка

    peek_first() – чтение без удаления

    advance() – удаление первого кадра

    drop_until(pts_threshold) – массовое удаление устаревших кадров

    update_keep_last(frame, pts) – сохранение последнего показанного кадра

3.2 Функции преобразования
python

video_frame_to_pts(frame_idx) → frame_idx * 1920
pts_to_video_frame(pts)        → pts // 1920
timecode_to_frame("HH:MM:SS;FF", fps) → h*3600*fps + m*60*fps + s*fps + f

3.3 Уравнение синхронизации
text

delta = frame.pts - (adjusted_audio_clock - audio_delay_samples)

if delta < -MAX_VIDEO_LAG (19200):  # кадр устарел на >400 мс → пропустить
    advance()
elif delta > FUTURE_HORIZON (960):  # кадр в будущем → показать keep_last
    return keep_last
else:                               # кадр вовремя → показать
    display(frame)

3.4 Коррекция дрейфа
text

measured_rate = Δaudio_clock / Δsystem_time
smoothed_rate = (1 - α) * previous_rate + α * measured_rate  (α = 0.3)

adjusted_clock = start_audio_clock + (sys_now - start_sys_time) * nominal_rate (48000)

Ограничение: |adjusted_clock - audio_clock| ≤ 24000 сэмплов (500 мс)
4. Формат .idx (Dalet)
4.1 Записи 0x193 (видео)

Размер: 68 байт (17 полей × 4 байта, little-endian)
Поле	Тип	Описание
f0	uint32	Сигнатура (0x193)
f1	uint32	Относительное смещение AVCC-сэмпла внутри сегмента
f2	uint32	Номер сегмента (0, 1, 2, …)
f3	uint32	Глобальный номер кадра
f7	uint32	Тип кадра: 1=non-IDR, 5/29/30=IDR, 27/28=IDR

Абсолютное смещение:
text

abs_offset = f2 * SEGMENT_SIZE + f1 - 4
SEGMENT_SIZE = 4_294_967_296 (4 ГБ)

4.2 Записи 0xC9 (аудио)

Размер: 68 байт (структура идентична 0x193)
Поле	Тип	Описание
f0	uint32	Сигнатура (0xC9)
f1	uint32	Смещение в сегменте
f2	uint32	Номер сегмента
f3	uint32	PTS первого AAC-фрейма
f7	uint32	Размер первого AAC-фрейма
f8	uint32	Младший байт содержит номер дорожки
4.3 Вычисление size2
text

size2[i] = abs_offset[i+1] - (abs_offset[i] + size1[i])   # для i < последнего
size2[last] = 0

Вычисляется отдельно для каждой дорожки (векторизованно через np.where).
4.4 Аудиочанки

Каждый видео-чанк (12 кадров = 23040 сэмплов) содержит аудиоданные для диапазона PTS:
text

start_pts = chunk_idx * 23040
end_pts = start_pts + 23040

Поиск записей: np.searchsorted(pts_array, [start_pts, end_pts])
5. Буферизация и поток данных
5.1 Видео-буфер (FrameRingBuffer)

    Максимальный размер: buffer_size кадров (600 по умолчанию)

    Политика переполнения: блокировка записи до освобождения места

    Управление: free_slots_required (25) – порог для возобновления загрузки

5.2 Аудио-буфер (AudioRingBuffer)

    Ёмкость: capacity_samples (1 440 000 = 30 сек)

    Политика переполнения: неблокирующая запись с ограничением max_ahead_samples (48 000 = 1 сек)

    Управление: _audio_write_enabled – временное отключение записи при паузе/seek

5.3 Жизненный цикл чанка
text

1. ChunkReader определяет границы чанка (video_start, audio_boundaries)
2. Чтение данных через WinSequentialReader (блоки 1 МБ, до 3 повторов)
3. Декодирование видео (filter_avcc → decode_sample → RGB24)
4. Декодирование аудио (AAC → float64 → try_write)
5. CHUNK_DECODED

5.4 Семафор декодирования

Одновременно декодируется не более 3 чанков:
python

_decode_semaphore = threading.Semaphore(3)

6. Система Seek
6.1 Гибридный seek (HybridSeekWorker)

    Поиск ближайшего IDR перед целевым кадром

    Чтение данных от IDR до min(IDR + 12 кадров, target + 12 кадров)

    Декодирование всех кадров, заполнение буфера

    Замена буферов: main ↔ background

6.2 Быстрый seek (JKL-перемотка)

Частота обновления: render_timer (40 мс при 25 fps). Формула пропускаемых кадров:
text

frames_to_skip = speed * fps * dt
accumulator += frames_to_skip
if accumulator >= 1.0:
    target_frame = current_frame + int(accumulator) * direction
    accumulator -= int(accumulator)
    _fast_seek_to_frame(target_frame)

Скорости: x2, x4, x8 (не циклично, максимум x8).
6.3 Ручной ввод таймкода

    Формат: HH:MM:SS;FF, MM:SS;FF, SS;FF, или просто число кадров

    Преобразование: timecode_to_frame() → seek_absolute()
